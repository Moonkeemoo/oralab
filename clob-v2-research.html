Polymarket CLOB V2 — Research Findings

01TL;DR

  • CLOB V2 went live April 28, 2026 (4 days ago) — full exchange contract replacement, no backward compatibility with V1 SDKs.
  • New collateral token pUSD (1:1 USDC-backed ERC-20) replaces direct USDC for collateral. Conversion required.
  • Order struct changed: removed salt, nonce, feeRateBps, taker; added timestamp, metadata, builder. Fees now in USDC at match-time (not shares at order-time).
  • Use TypeScript: @polymarket/clob-client-v2 v1.0.2 is actively maintained (7 days ago). py-clob-client-v2 exists but is "early-stage successor" with no migration docs — risky.
  • ERC-1271 signatures supported — smart contract wallets are first-class in V2. This unlocks clean BYO-wallet UX for multi-user (P3+).
  • Three new alpha sources unlocked: Sports WebSocket (real-time scores, no auth), builder rewards (register for fee-share), RTDS for crypto markets.
  • v1 still partially works — py-clob-client v0.34.6 hits order_version_mismatch on every order since ~April 27. Production v1 instances bleeding.

04Three new alpha sources unlocked by V2

Sports WebSocket

wss://sports-api.polymarket.com/ws
  • No auth required
  • No subscribe message (auto-streams all active events)
  • Real-time scores, periods, game status
  • NFL, NHL, MLB, NBA, CBB, CFB, Soccer, Esports, Tennis
  • Server pings every 5s; respond with pong <10s or disconnect
  • Edge: react to score changes faster than market price adjusts
  • For ora-v2: independent SignalSource for SportsScoreReactor strategy

Builder rewards

on-chain builder attribution code
  • V2 adds builder field to order struct
  • Routing flow through your builder address shares fee revenue
  • $1M reward pool announced at V2 launch
  • Useful for institutions + frontends; ora-v2 can register
  • Free side-revenue if registered correctly from day 1
  • For ora-v2: register builder address, populate field on every order

RTDS — Real-Time Data

wss://ws-live-data.polymarket.com
  • TS SDK: @polymarket/real-time-data-client
  • Streams crypto prices (Binance, Chainlink) + comments
  • Useful for crypto markets (BTC, ETH price-bounded)
  • Lower latency than polling external APIs
  • For ora-v2: optional supplement for crypto-strategy in P4+

05Impact on ora-v2 architecture

Architectural decisionHow V2 affects it
Backend stack Locked to TypeScript. py-clob-client-v2 too risky to use in production.
Order signing Cannot port v1's signing logic. Use clob-client-v2 + viem + @polymarket/clob-order-utils. Sign with new struct (timestamp/metadata/builder).
Wallet model (P1 solo, P3 multi-user) P3 BYO-wallet flow gets dramatically cleaner with ERC-1271. Smart wallet (Safe / AA) where user controls key, ora-v2 backend is delegated co-signer. Revocable any time. Cleaner than custodial.
Collateral handling Add USDC↔pUSD conversion. Display balances in pUSD-units; convert for user-facing UI if confusing. P1: deposit/withdraw via Polymarket's standard pUSD flow.
Fee accounting Fees in USDC at match-time, not shares at order-time. PnL math simpler (no share-fee deduction). Budget tracking accounts for USDC fee post-fill.
Sports strategy (P4+) SportsScoreReactor reading from wss://sports-api.polymarket.com/ws is a new strategy class. SportsPreEventStrategy still valid (uses external odds).
Builder revenue Free additional revenue stream if we register builder address and populate every order. Worth doing in P1.
v1 invariants port Most still apply (M1-M5, D1-D3, O1-O2 from SPEC.md). Some change: no more feeRateBps mismatch (fees server-side); no more order_version_mismatch (one V2 contract per market type).
API.md doc Order signing section needs full rewrite. Contract addresses table needs V2 values. SDK template uses clob-client-v2 + viem. Sports WS section to add. pUSD section to add.
